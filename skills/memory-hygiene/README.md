# memory-hygiene

给编码 agent（ZCode / Claude Code 等 SKILL.md 类 harness）的记忆文件卫生规范。核心主张一句话：**记忆每一条要么引导行为、要么污染行为——记终态，别记流水账；说做什么，别说别做什么。**

本项目由 GLM-5.3-Flash 构建。

## 为什么需要它（2026-09-13 实测审计）

对 10 个项目 / 91 个记忆文件的一次审计发现三类症状，全部有会话日志实证：

1. **日志体膨胀** — 记忆文件被当成会话流水账逐轮追加：最大单文件 134KB（55 轮策略史），另一个文件在单个会话内被重写 136 次。每次 recall 都把几万 token 的过程叙事重新注入上下文，真正的行为指引被稀释。
2. **粉红大象** — 记忆里高密度否定式指令（"禁止/不要/避免/不得"）。LLM 没有抑制机制，"别做 X" 等于把 X 作为活跃概念注入每次会话；研究一致表明负面指令适得其反（讽刺过程理论 / negative prompt 成为强先验）。错误示范的生动叙事（"被点名批评"、"连续三轮"、"30K 作废"）同理——每次 recall 都重新教一遍错误模式。
3. **结构性损坏** — frontmatter 被正文打断、索引文件里出现字面行号前缀（`29\t`）、单条索引行膨胀到数千字。

修复后 6 个大文件平均压缩 ~70%，这套规范本身就是这个 skill。

## 安装

```bash
# ZCode（用户级 skill）
cp skills/memory-hygiene/SKILL.md ~/.zcode/skills/memory-hygiene/SKILL.md

# Claude Code
cp skills/memory-hygiene/SKILL.md ~/.claude/skills/memory-hygiene/SKILL.md
```

更有效的用法是在用户级指令文件（AGENTS.md / CLAUDE.md）的记忆规则里直接引用它——skill 靠语义匹配触发，规则引用则保证每次写记忆时规范一定在场：

```markdown
- 记忆写法遵循 memory-hygiene skill：正向表述优先（负面约束配正向替代同句出现）、
  记终态不记流水账（单文件超 ~8KB 时重写为终态+归档全史到 memory-archive/）、
  错误示范只留最小痕迹（规则+一行证据+检查方法，用户原话除外）、索引行 ≤120 字符。
```

## 规范摘要

**该记什么**：用户偏好与反馈（保留原话）、项目已定决策及理由、终态（交付了什么/定了什么/当前数字）、带触发条件的可复用坑、外部资源指针。

**写法四则**：
- 说行为，不说禁令——"提交前禁止包含绝对路径" → "对外内容用相对路径与占位符书写"；负面约束不可避免时同句配正向替代。
- 终态优先于叙事——决策和最终数字入记忆，迭代史压成一行（"终版=X（过程三案被否，详见归档）"）。
- 错误痕迹最小化——教训=规则+一行证据+早发现手段；删事故复盘、删指责性措辞、删坏例子原文。用户原话是例外：引用原文，那是 ground truth。
- 不确定就写不确定——被数据推翻的猜测立即退役，留在记忆里等于每会话重打一次已输的仗。

**大小预算**：单文件软上限 ~8KB，超了就重写为终态、全史挪到 `memory-archive/`（索引外）；索引行 ≤120 字符；索引文件 ≤10KB。

**审计模式**（skill 内含完整 grep 清单）：大小扫描 → 否定词密度 → 叙事气味（被点名/教训/作废/浪费）→ 过期钩子 → 结构损伤 → 对会话日志核验"用户说过/定过"。

## 设计取舍：为什么读侧交给 harness 内置、写侧靠规范

本 skill 刻意不含任何 hook。读侧（会话启动自动注入记忆索引）是 harness 内置能力，hook 召回与之重叠 90%；写侧如果做成固定时机强制写入（AOP 式"memory 夹工作流"），在加上预算约束之前只会把流水账问题自动化。所以正确的分工是：**读侧全自动，写侧由 agent 按规范判断**——本 skill 就是那个规范。
