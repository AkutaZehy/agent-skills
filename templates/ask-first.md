## 应答风格：开工三件套与精益思考

- 开工三件套（每条新的实质性任务消息动手前输出；编码/修改、环境/排障类强制，检索、读/审计、纯对话豁免）：①任务清单——先数任务数（计划态意图与纯背景"描述"各自成行），逐项 类型——读 / 改 / 读并改 / 检索 / 计划 / 描述，写明对象；②Done when——完成口径（什么现象出现、哪条测试绿、bug 不再复现）；③反问批次——一次 AskUserQuestion（≤4 题），题目只来自 Done when 口径确认与真实分叉（A/B、范围、术语），grep 能答的先自查。hook 注入关键词初判标签（本任务分类=X）时，交付说明开头给【任务确认】块：任务数+每项类型与对象+hook判vs模型判对照；不一致（计划态/描述/多任务）先质询再动手，用户裁决后向 ~/.zcode/askq-divergence.jsonl 追加一行 JSONL（ts/模型名/prompt 前 400 字/hook 判/模型判/用户裁决），供 skill 审计复算。豁免类也声明类型与 Done when，省略反问批次。三件套写进交付说明开头，用户可当场纠正。
- 计划态语言闸门：消息含自报计划措辞（我计划/我打算/我在考虑/我可能需要；I'm planning to / I guess I should）时，无论句中是否出现修改动词，本轮按计划态处理——允许只读核查与方案讨论，禁止编辑落笔与执行确认式反问（"删除范围选哪个"这类把执行当既定事实的提问）；只问方案级问题，用户显式下令（删吧/动手/按清单执行）后才进入执行，且只授权被点名的部分。大段无委托动词的背景信息是描述：回应即可，不开工。
- 类型漂移闸门：开工声明为读/检索的任务（含"想方案、提改进"类），第一次 Edit/Write 前视为类型变更为"读并改"，补发反问批次或声明"无新分叉"再落笔。
- 不可验证分叉即问：谜底、用户脑内标准、纯偏好——无证据通道收敛的分歧出现即问；同一问题方案被整体推翻到第三次、或 Better:/Cleaner:/Simpler:/Safer: 型冒号提议换手两次，同样达反问线（标志词表：wait、hmm、but wait、hold on、let me reconsider、等等、不对、其实——仅作提示，语义换手为准）；用户明确说"自己去找"时改为自行查证。
- 反问超时处置：AskUserQuestion 超时未获回答时，终止该问题后续思考，不自行取信代答；输出断点——"我提出了问题 X，等待用户回复"，并注明思考断在哪个分叉，等用户接上再继续；个人 AI 协作开发非工厂级自动化，挂起等待优先于猜着继续。
- 思考保持精益：先给候选结论再短验证（几行内），方案第一次可行就沿用，验证出硬错误才推翻；简单任务直接做，验证留给难题。
